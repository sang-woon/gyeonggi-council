# 출시 후 모니터링 가이드

Play Store 공개 출시 이후 모니터링 항목과 대응 방안.

## 1. Play Console 모니터링 대시보드

| 메뉴 | 확인 주기 | 임계치 |
|------|---------|--------|
| **통계 (Statistics)** | 일 1회 | 신규 설치 추이 |
| **품질 > Vitals (Android Vitals)** | 일 1회 | 크래시율 < 1.09%, ANR률 < 0.47% (Bad behavior 임계치) |
| **품질 > Pre-launch reports** | 출시 후 1회 | Google 자동 검사 결과 (실 디바이스 5종) |
| **사용자 의견 (Reviews)** | 일 1회 | 평점 ≥ 4.0, 신규 리뷰 응답 |
| **정책 > 위반 사항** | 주 1회 | 0건 유지 |

## 2. Android Vitals 핵심 지표

### 크래시율 (Crash Rate)
- 임계치: **1.09%** (Google "Bad behavior" 마커)
- 본 앱은 WASM 기반 → **메모리 OOM이 가장 흔한 사유**
- 대응: 큰 파일(20MB+) 처리 시 사용자에게 사전 경고 표시

### ANR률 (App Not Responding Rate)
- 임계치: **0.47%**
- 본 앱은 메인 스레드에서 WASM 호출 → **5초 이상 블록 시 ANR**
- 대응: 페이지네이션 비동기 처리, 진행 표시 UI 강화

### 슬로우 시작 (Slow Startup)
- 임계치: 콜드 스타트 5초 이상
- 본 앱: WASM 4MB 로딩 + Capacitor + React = ~3~4초 예상
- 대응: 스플래시 화면으로 사용자 체감 단축

## 4. 정기 보고 사이클

### 일 단위 (주말 제외)
- Play Console Vitals 확인
- 신규 리뷰 응답
- 신규 크래시 트레이스 확인

### 주 단위
- Vitals 추이 그래프 (1주일)
- 사용자 의견 카테고리화 (UX 불만 vs 기능 요청 vs 크래시)
- 다음 주 백로그 우선순위 조정

### 월 단위
- 설치 수·활성 사용자 수 보고
- 크래시 Top 5 → 패치 릴리즈 계획
- 리뷰 카테고리 정리 (피드백 → 이슈/PR로 전환)

## 5. 단계적 출시 (권장)

| 단계 | 비율 | 기간 | 진행 조건 |
|------|------|------|----------|
| 1차 | 5% | 3일 | 크래시율 < 0.5%, 네거티브 리뷰 0건 |
| 2차 | 20% | 1주일 | 크래시율 < 1.0%, ANR < 0.5% |
| 3차 | 50% | 2주일 | 평점 ≥ 4.0, Vitals 정상 |
| 4차 | 100% | 안정화 | 1주일 모니터링 후 안정 시 |

각 단계 진행 시 Play Console > Production > 단계적 출시 비율 조정.

## 6. 비상 대응 절차

### 심각한 버그 발견 시 (예: 데이터 손상, 보안 결함)

1. **즉시 단계적 출시 중지** (Play Console > 단계적 출시 일시 중지)
2. 30분 내 핫픽스 브랜치 생성 (`hotfix/v1.0.1`)
3. 패치 → 빌드 → 내부 테스트 (24시간 내)
4. 재출시: 새 버전(v1.0.1) 단계적 5% → 100% (가속 가능)
5. 사용자 공지 (선택): 매장 등록정보의 "최신 변경사항"에 언급

### Google에서 정책 위반 통지 시

1. 통지 메일 정독, 위반 사유 식별
2. 24시간 내 회신 + 수정 계획 제출
3. 수정 패치 → 재제출 (Play Console > 정책 위반)
4. 항소 사유 있을 시 `play_console_rejection_appeals.md` 활용
